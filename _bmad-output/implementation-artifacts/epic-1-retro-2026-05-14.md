### What Went Well

- Foundation capabilities were delivered and integrated: FastAPI app, health/readiness behavior, configuration loading, and container publish workflow.
- Dependency consistency improved through `mtv_dl` source-of-truth alignment to `pyproject.toml`.
- Team showed strong traceability discipline from PRD/FRs to stories and acceptance criteria.
- Concurrency hardening direction improved across related stories with clearer lock and shared-state intent.

### Challenges and Friction

- Status tracking drift between story files and `sprint-status.yaml` reduced confidence in true completion state.
- Concurrency work became fragmented: follow-up hardening stories remained open while later story status appeared closed.
- Some story completion claims lacked enough evidence at review time, creating avoidable revalidation loops.
- Database refresh cadence/status/logging story (1.10) remained unfinished, leaving an important boundary incomplete.

### Recurring Patterns

- **Process pattern:** completion status was updated before implementation/review evidence was consistently aligned.
- **Quality pattern:** targeted tests were added, but confidence gaps remained in cross-story regression behavior.
- **Technical debt pattern:** deferred concurrency and validation items repeatedly reappeared in reviews.
- **Coordination pattern:** planning-to-execution sequencing drift occurred (Epic 2 sub-stories progressed while epic state remained backlog).

### Root Causes (System-Focused)

- Definition of done was applied inconsistently across implementation, review, and tracker updates.
- Story ownership handoff criteria were not strict enough at transition points (`in-progress` -> `review` -> `done`).
- Cross-epic sequencing governance was not explicit when backend prerequisites were still unsettled.

### Lessons Learned

1. A single status source is only useful when it is reconciled with story evidence before transitions.
2. Concurrency and lifecycle behavior should be closed as a coherent slice, not as partially completed fragments.
3. Review quality improves when acceptance evidence is captured directly in story records before state changes.
4. Epic readiness should include dependency readiness checks, not only story count checks.
